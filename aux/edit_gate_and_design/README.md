# edit_gate_and_design

Kept against rejected edits and the evidence behind the design principles. All read the edge table of `python -m aux.rule_coding.edges build`. `design designev` also reads the cache of `python -m aux.cost_appendix.compaction compute`, so run `cost_appendix` first when starting from empty caches (`scripts/aux.sh all` already does).
`python -m aux.edit_gate_and_design.edges_contrast [holm]` writes `mech_edges.md` (kept and rejected edits on the four-term split and on dev success) or `mech_edges_holm.md` (the rule-category contrasts under Holm's correction).
`python -m aux.edit_gate_and_design.design batching|designev|selrules` writes `mech_batching.md` (cost at the seed's calls per turn), `mech_designev.md` (what explains an edit's token change, the cost-aware gate) and `mech_selrules.md` (four acceptance rules on the task model); `designev` reads `compaction.json` of `aux.cost_appendix.compaction compute`.
`python -m aux.edit_gate_and_design.implications_fig` draws `mech_implications4.{pdf,svg}` from `selrules.json`, `designev.json` and `batching.json` (edits kept under four acceptance rules, what explains an edit's token change, log rho at the seed's calls per turn, kept against rejected edits) and writes the drawn numbers to `mech_implications4_numbers.json`.
`python -m aux.edit_gate_and_design.tiebreak`, then `tiebreak_record`, writes `mech_tiebreak.md` (whether success or cost separates a candidate from its parent, and the cost tie-break replayed on the optimizers' candidates). Its seed-vs-seed token noise floor also pairs the one tau3 and one AutoBench seed dev evaluation whose runs the assets no longer hold, with their per-task input tokens from `aux/data/seed_dev_extra.json`.
